# 候选 trigger：用一小段提示撬动后训练习惯

状态：**草稿，待测试**。每段都有来源，但还没在我们的题目上做对照实验。

## 前提

模型保留了像人一样说话的能力，后训练让它默认选了另一种说法。证据：

- URIAL（Lin 等，ICLR 2024）：对齐模型和 base 模型在绝大多数位置选同一个词，对齐模型选的词基本都在 base 模型的前 5 个候选里。差异集中在开头几个词、话语标记和免责声明。只用 3 个示例加一段系统提示，base 模型就能达到对齐模型的水平。
- Nudging（Fei 等 2024）：对齐改变的主要就是这一小批文风词。
- Prover-Verifier Games（OpenAI，Kirchner 等 2024）：只按对错优化会让输出难以核对，改变训练目标后可读性回升。
- Clark 等（2026）：Claude Opus 5.5 在难读特征上明显少于 Opus 5，说明训练能修回来。

所以 trigger 要做的，是把排在后面的那个像人的说法提到前面。

## 写法原则

1. **示例为主，描述为辅。** few-shot 的文风模仿准确率最高是 zero-shot 的 23.5 倍，4–5 组示例就够（Jemama 等 2025）。每个 trigger 配 4 组真实原话的前后对照。
2. **管住开头、过渡、结尾。** 对齐的痕迹集中在这三处（URIAL、Nudging）。
3. **给反模式起名，说明读者为什么难受。** 照 Anthropic 的 mannered prose 提示。
4. **不列禁词。** 禁词表会被当成提示（Antislop；DeepSeek V4 用户反馈）。
5. **一个 trigger 只管一个习惯。** 笼统的「写得像人」改不动深层文风（Rallapalli 等 2026）。

## 评测方案

### 主指标：读者能不能看懂

一项 150 人的研究发现，读者觉得 LLM 写的通俗摘要和人写的一样清楚，但答理解题时读人写版本的人答得更好；可读性公式也和人的判断对不上。所以口癖计数只作辅助，主指标是理解度。

1. **理解题。** 每道写作题事先写好 5 道事实题（答案来自题目给的素材）。让另一家模型只读产出的文字作答，看答对几道。
2. **信息保留。** 对照素材的事实清单，数产出里保留了几条、有没有编造。
3. **盲评偏好。** 打乱顺序、去掉标签，由另一家模型评「哪篇更好懂、更像这个场合的人会写的」（GPT 的产出交给 Claude 评，Claude 的产出交给 GPT 评）。有条件时加人工评一小部分。
4. **辅助指标。** `scripts/scan.py` 各模型密度、含否定的句子占比、堆叠名词和单字动词数、字数。

### 题目

- **对话集**（只测 `gpt-defensive`）：molang163 的 16 道日常题，加 5 道工作汇报题（「你刚改完 X，写一段完成汇报」）。
- **写作集**（测其余 trigger）：8 类，每类 2 题，每题附素材和 5 道理解题：工作周报、技术文档、给用户的公告、课程论文段落、公众号短文、产品介绍、小说片段（主要测 DeepSeek）、英文论文摘要（测 `claude-en.md`）。

### 条件

| 条件 | 说明 |
|---|---|
| 不加 | 基线 |
| 指令式 | 只有反模式定义和改法，不带示例 |
| 示例式 | 本目录现在的写法 |
| 示例式 + 多候选 | 加一句「先想三种说法，选最像这个场合的人会写的那种」（参考 Verbalized Sampling） |

每个条件每题跑 3 次。GPT 用 `codex exec --ephemeral`（不留会话记录），Claude 用 `claude -p`，DeepSeek 用其 API。

### 通过标准

同时满足才保留：理解题正确率不低于基线；信息保留不低于基线、没有新增编造；盲评胜率 60% 以上。没通过的删掉或重写。结果写进 `evidence/`。
