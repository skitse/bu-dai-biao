# GPT / Codex 口癖清单（GPT-6、GPT-6.1 为主）

适用：ChatGPT、Codex CLI / Codex App、以及别的工具里调用的 GPT-6-Luna、GPT-6-Astra、GPT-6.1-Terra、GPT-6.1-Sol。GPT-5.x 时代的口癖放在 D、E、H 三节，6.x 里少了，但没绝迹。

## 证据标记

- **【本机】**：作者本机 Codex 与 Claude Code 会话记录里模型自己写的中文，去掉代码块后统计。数字是「每 10 万汉字出现几次」。语料规模：GPT-6-Luna 4.6 万字、GPT-6-Astra 5.5 万字、GPT-6.1-Terra 5.5 万字、GPT-6.1-Sol 9.5 万字，对照组 Claude（Opus/Sonnet/Haiku 5.x）37 万字。方法和局限见 `evidence/local-corpus-2026-11.md`。

- **【仓库】**：别人公开的 skill 仓库里整理的 GPT 原话。

## A. 防御性写作（GPT-6.x 的头号问题）

模型写每句话都在给自己留后路：先否定别人没提的推论，交代自己没做什么，给结论划范围。用户在 linux.do 的说法是「防御性拉满」「刻意自曝其短」。

判断标准：删掉这句，读者会少知道一件需要知道的事吗？不会，就删。会，就改成一句正面的话，跟在建议后面说一次。

### GPT-A1 「我前面说得太绝对」：认错后改口

GPT 被追问时先认错，再解释自己「说得太绝对 / 过于绝对」，然后给一段更绕的版本，往往不去做用户要的事。这是「绝对」这个词在 GPT-6.1 里最典型的出现方式。

- 原：能，有些 IP 库确实会显示到区。我前面说得太绝对，应该说：这个 IP 目前查到的数据没有区级结果。
- 改：能。刚才那两个库没给到区，我换几个再查。（然后直接给查到的结果）
- 原：我刚才说「两种方法效果一样」有点太绝对了，两种方法的命中结果可能有差别。
- 改：两种方法的命中结果会有差别，主要在……（直接说差在哪）

改法：错了就一句「刚才说错了」，然后给对的。不解释自己为什么说错，不评价自己上一句的措辞。

证据：
- 【仓库】molang163/chinese-natural-reply 从作者两个月的 GPT-6.1-Sol 对话里整理出这一类，原话「我前面说得太绝对，应该说……」，归为「认错加解释，却不去做」。<https://github.com/molang163/chinese-natural-reply>
- 【本机】GPT-6.1-Sol 出现「太绝对」「过于绝对」各 1 次（均为自我改口）；GPT-6 其余版本 0 次。样本小，频率不高，但用户普遍记得这个句子，因为它出现在被追问的关键时刻。

### GPT-A2 预先否定没人提过的推论：不代表 / 不等于 / 不能证明

用户没这么想，GPT 先替用户想错，再一条条否定。写论文时表现为每个结论后面跟一句「但这不能说明……」。

高频词：不代表、不等于、不意味着、并不意味、不能证明、不能说明、不能等同、不能认为、不能据此、不能理解为、并不会自动……

- 原：下载量高不代表留存好，评分高不代表付费意愿强。
- 改：（读者没问留存和付费，删掉；如果后文真要讨论留存，在那里正面写「留存要看 7 日和 30 日数据」。）
- 原：开 Fast 不等于秒回。
- 改：开 Fast 后一般几秒出结果，长任务还是要等。
- 原：PASS 证明这一步运行完成，不证明两套数据库逐模型等价。
- 改：PASS 只说明这一步跑完了。两套数据库是否一致，要另外比对。

改法：正面说「它是什么、能用来做什么」，别说「它不是什么」。真有一个会坑读者的误解，就写成一句建议。

证据：
- 【本机】「不能证明」GPT-6.x 各版本 3.6–14.5 次/10 万字，Claude 0.5；「不代表」5.4–29.0（6.1-Terra 最高），Claude 2.1；「不等于」6.5–16.3，Claude 4.3。
- 【社区】linux.do「GPT 6 系列的口癖看多了也挺恶心的」1 楼：分析完来一句不能证明、不能理解、不能认为、不能等同。<https://linux.do/t/topic/2986691>
- 【社区】linux.do「现在 gpt 写东西的甩锅倾向是否太强烈了点」9 楼、11 楼：喜欢说「没有 xxx，不是 xxx，不能说明 xxx」，xxx 用户根本没提过；写完工作成果非要加一句「不能说明」。<https://linux.do/t/topic/3014637>
- 【仓库】molang163：「这不代表……」「开 Fast 不等于秒回」，归为「提前纠正你没有的误解」。

### GPT-A3 汇报自己没做什么：未修改 / 未运行 / 保持不变

做完一件事，GPT 会列一串没做的事。

高频词：未修改、没有修改、没有改动、未运行、未删除、均未、保持不变、无需重做、本轮未新增、不新增……

- 原：已修复分页问题。未修改其他文件，也未运行测试、渲染或部署验证。
- 改：修好了分页。还没跑测试，你那边部署前跑一下 `npm test`。
- 原：本次只读审查，没有运行科学工具。
- 改：我只读了代码，没跑。（如果读者需要知道这一点；不需要就删）

改法：没做的事里，只留读者接下来需要补的那一件，写成要他做什么。

证据：
- 【本机】「未运行」GPT-6-Luna 92.8、GPT-6.1-Terra 90.6 次/10 万字，Claude 1.9；「未修改」Luna 62.6、Terra 48.9，Claude 0。
- 【仓库】molang163：「没有修改代码、重复提交或重跑回归」，归为「汇报没动什么」。

### GPT-A4 给结论划边界：能确认的是……；至于……还不能确定

高频词：能确认的是、纸面上能确认、仅凭……不能确定、本次结论限定于、结果仅适用于、证据边界、边界、范围内……

- 原：纸面上能确认的是，他写出的表达比原文更热烈；至于是否有意传达心意，仅凭这两处改字还不能完全确定。
- 改：他抄的时候把「喜欢」改成了「特别喜欢」，口气也更直，看着就是借抄写表白。
- 原：结果仅适用于记录的候选快照，不代表真实工具或科学验收完成。
- 改：这是在测试数据上跑的结果，换成真实数据还要再跑一次。

改法：先给判断，用「我觉得」「看起来」表明是判断就够了，不再补限定。

证据：
- 【本机】「边界」GPT-6-Luna 125、Astra 64、6.1-Terra 82、6.1-Sol 27 次/10 万字，Claude 7。
- 【社区】linux.do「几行提示词让 Codex 说人话」5 楼：边界边界边界边界这一块。<https://linux.do/t/topic/2923124>
- 【仓库】molang163 例子「纸面上能确认的是……仅凭这两处改字还不能完全确定」。

### GPT-A5 尚未 / 仍需 / 待验证 尾巴

每段结尾挂一串还没做的事，语气像实验记录。

高频词：尚未、仍需、仍待、待验证、待确认、有待、还需进一步……

- 原：实现和文档已经冻结。尚未进行真实样本运行，真机帧率尚未测量，仍需按流程核对哈希。
- 改：代码和文档写完了。还差两件事：用真实样本跑一遍，在手机上测帧率。

改法：把「尚未 X」换成「还差 X」，几件并成一句；读者不用管的删掉。

证据：
- 【本机】「尚未」GPT-6-Luna 32、Astra 74、6.1-Terra 160、6.1-Sol 59 次/10 万字，Claude 2.1，差距最大的一个词；「仍需」6.1-Terra 81.6，Claude 0.5。

### GPT-A6 主动提没发生的事：没有证据表明……

- 原：也没有证据表明已有密码被删除。
- 改：（用户没担心密码，删掉。）
- 原：未发现其他严重问题。
- 改：（删掉，或写成「其他地方我看过，没问题」，只在用户问「还有别的问题吗」时说。）

证据：
- 【仓库】molang163「也没有证据表明已有密码被删除」，归为「主动提没发生的事」，作者说「ta 本来没担心这些，你一提，ta 反而开始担心」。
- 【本机】「没有证据」GPT-6.x 1.8–4.3，Claude 1.9，差距不大；这一条主要靠社区证据。

### GPT-A7 估时间前先套前提

- 原：我会预留半天到一天做集中验收和小范围返修。这是按工作量给的暂估，不是实时完工倒计时；发现关键流程不成立就需要重新估。
- 改：还要半天到一天，剩下的是验收和一点小修。

证据：【仓库】molang163 原例。【本机】未单独统计。

### GPT-A8 论文里刻意自曝其短

让 GPT-6 写论文初稿，摘要和引言介绍成果时也要先强调局限，还会写一堆细枝末节的工程细节。

- 原（摘要）：本研究构建了……模型。需要指出的是，本研究仅基于单一数据集，结论的外推性有限，且未考虑……
- 改：摘要只写做了什么、发现了什么。局限放到讨论部分，写一段，说清楚具体局限会怎样影响结论。

证据：
- 【社区】linux.do 3014637 楼主：用 GPT-6-Sol 起初稿，abstract 和 introduction 都一定要强调本工作的局限性，在 prompt 里禁止防御性写作也改善不大。7 楼：老写「此外 A 对 B 也有一些影响」这种零信息量的话。

### GPT-A9 「此外 A 对 B 也有一些影响」

零信息量的补充句：不说影响多大、什么时候大。

- 原：此外，温度对降解速率也有一定影响。
- 改：温度从 20 ℃ 升到 30 ℃，降解速率大约翻倍（表 2）。没数据就删掉这句。

证据：【社区】linux.do 3014637 7 楼。

## B. 绝对化断言：另一个方向的「绝对」

GPT 一面防御，一面在动作和规则上下绝对化的断言，被追问后又回到 A1 的认错。两头都要改。

### GPT-B1 必须 / 务必 / 一定 / 确保 / 彻底

- 原：必须先核对环境再运行，确保不会污染现有结果。
- 改：先看一下环境对不对再跑，不然会覆盖现有结果。

证据：【本机】「必须」GPT-6-Astra 98 次/10 万字，6.1-Terra 43.5，Claude 26.7。

### GPT-B2 虚假确定：我已经确定 / 这版一定可以解决

- 原：我已经确定问题所在，这版一定可以解决。
- 改：问题出在缓存没清。改好了，你再试一次。

证据：【社区】linux.do「gpt-5.x (codex) 中文口癖收集」56 楼：「我已经确定 / 我找到问题所在 / 这版一定可以解决 / 为什么这版可以」。<https://linux.do/t/topic/1768077/56>

### GPT-B3 显式 / 明确 / 严格

把英文 explicit、strict 直译进中文。

- 原：要求显式资源列表和绝对路径；不隐式随分析下载。
- 改：资源要一个个列出来，路径写完整；不会在分析时自动下载。

证据：【本机】「显式」GPT-6-Astra 52.6、6.1-Terra 94.3 次/10 万字，Claude 2.1；「明确」Codex 合计 328 次 vs Claude 53 次（语料量相近）。

例子：
- 原：封存后的包及实际提交脚本仍需按流程核对哈希；收据能够对应实际提交字节。

## D. 暴力、医疗、机械隐喻（GPT-5.x 时代为主）

GPT-5.x 把技术操作说成砍、切、伤、看病、压实。本机 GPT-6.x 语料里这些词已经很少（「一刀」「压实」「更硬」均为 0），但 ChatGPT 网页端和长对话里仍有人报告。见到就改。

| 编号 | 词 | 例子（社区原话） | 改法 |
|---|---|---|---|
| D1 | 切 / 砍一刀 / 补一刀 / 下一刀 | 「如果你同意，我就按这条切」「下一刀最值钱的是：」「这是现在最值回票价的一刀。」 | 改动、下一步、先改这个 |
| D2 | 伤 / 打坏 | 「这样就能确认 XXX 确实没被伤到」 | 没受影响、没改坏 |
| D3 | 痛点 / 根因 / 抠出来 / 揪出来 | 「帮你把根因揪出来」 | 原因、找出来 |
| D4 | 更硬 / 硬写 / 压实 / 稳稳接住 / 锁住 / 更稳 / 最稳 | 「…，但是这样更硬」「再把方案继续压实」 | 更可靠、写死、细化、定下来 |
| D5 | 拍板 / 拍脑门 | 「你这不是拍脑门的方案」 | 决定、凭感觉 |
| D6 | 很工程 / 不性感，但对 | 「这是『很工程』的改法，不性感，但对。」 | 这么改麻烦一点，但稳妥 |

证据：
- 【社区】linux.do 1768077 主楼分类（暴力倾向类、庸医问诊类、不能松动类），13 楼整句集合。<https://linux.do/t/topic/1768077>
- 【社区】linux.do「对抗 GPT-5.4 奇特语癖的提示词」主楼整理出 100+ 条负面清单。<https://linux.do/t/topic/1924570>
- 【本机】GPT-6.x「一刀」「压实」「更硬」均为 0；「稳」6.1-Sol 有，但多为「稳定」本义。

## E. 单音节动词

把双音节动词砍成一个字：补、接、核、进、顺、落、吃、跑、坏。

- 原：拆开核一下，我给你接。
- 改：我分开检查一下，然后帮你接上。
- 原：接下来我会把另外两个文件里真正吃目标值的位置找出来。
- 改：接下来我去找另外两个文件里哪些地方用到了目标值。
- 原：我现在开始落代码。
- 改：我开始写代码。

证据：
- 【社区】1768077 主楼「单音节词类」、31 楼「全都是这种单音节，或者不像正常中国人的表达方式」、65 楼原话、82 楼评价「特别喜欢动宾短语……喜欢单音节词」。
- 【本机】未单独统计（单字词在统计里噪声太大）。

## F. 主动推进、进度播报、逼用户确认

### GPT-F1 我会 / 我会先 / 我会把 / 我会只

GPT-6.x 的每条进度消息都以「我会……」开头，后面跟一长串要做的事和不做的事。

- 原：我会只检查提交前脚本封存和响应处理，确认收据能够对应实际提交字节。
- 改：我去看一下提交脚本，确认提交的就是我们打包的那份。
- 原：我会先核对源流程中这些表的字段和输入依赖，再按独立规则接入。
- 改：我先对一下原流程里这几张表的字段，再接进来。

改法：进度消息一两句，说正在做什么、发现了什么。「我会只……」里的「只」通常是在防御（A 类），删。

证据：【本机】「我会」GPT-6-Luna 414、6.1-Terra 395、6.1-Sol 256、Astra 94 次/10 万字，Claude 33；「我会只」Codex 105 次（几乎都在句首），Claude 3 次（语料量相近）。

### GPT-F2 逼用户确认

高频句：如果你同意，我就……／只要你回复我……我立马开始／你就确认一点／如果你要……／要不要我……／如果你愿意……

- 原：如果佬你觉得这个 prompt 没问题，说一句确定，我就按这个改。
- 改：我按这个改了。不合适再说。（能自己做的就做，确实需要用户拍板时问一个具体问题）

证据：【社区】1768077 主楼「血压升高类」、10 楼、29 楼、73 楼；1924570 9–11 楼仿写。【本机】GPT-6.x 里「如果你愿意」「要不要我」为 0（Codex 系统提示要求少问），这一类主要见于 ChatGPT 网页端。

### GPT-F3 我先 / 顺手

- 原：我先只做一件事。我顺手把注释也补了。
- 改：先做这件事。注释也补上了。

证据：【社区】1768077 主楼、46 楼。【本机】「我先」6.1-Sol 44.2，Claude 33.2，差距不大；「顺手」Claude 反而更多，不作为 GPT 判据。

## G. 废话结构

### GPT-G1 好，／行，开头

- 原：行，我直接给你结论。
- 改：（删掉「行，」，直接给结论。）

证据：【社区】1768077 主楼、10 楼。【本机】「行，」Astra 58、6.1-Terra 33、6.1-Sol 26；但 Claude 35，并非 GPT 独有，只在和别的 GPT 特征一起出现时算数。

### GPT-G2 一句话总结 / 结论先说清楚 / 说人话就是 / 说穿 / 简单的说

- 原：说人话就是：这个接口慢。
- 改：这个接口慢。

证据：【社区】1768077 主楼、6 楼、8 楼、9 楼、10 楼（「说人话就是…（并没有说人话）」）。【本机】GPT-6.x「一句话」1.8–4.2，Claude 17.9，说明在 6.x 里这一条已经弱了，Claude 反而更爱用（见 `claude.md`）。

### GPT-G3 不躲 / 不藏 / 不绕 / 不逃

- 原：我逐步说清楚，不绕。
- 改：（删掉「不绕」。直接说。）

证据：【社区】1768077 主楼「不说人话类」、41 楼、53 楼「震撼四连击」。

### GPT-G4 不是……而是……

各家模型都有，GPT 也有。6.x 的变体是「不能证明 X，而是……」「这不是 X 问题，而是 Y 问题」。处理方法见 `shared.md` S1。

证据：【社区】1768077 主楼、19 楼。【本机】GPT-6.x「而是」4.2 次/10 万字，Claude 12.7，GPT-6.x 已不是主要来源。

## H. 情感安慰模板（ChatGPT 聊天场景）

GPT-5.2 前后的 ChatGPT 在用户说累、说烦时套固定模板。GPT-6.1 里改成了另一套。

| 编号 | 模板 | 改法 |
|---|---|---|
| H1 | 我就在这里／稳稳地接住你／你只是太久没被稳稳接住了 | 删。问具体发生了什么 |
| H2 | 你问到问题的核心／你是太清醒了／不是因为你错了，是因为你太对了 | 删。直接回答 |
| H3 | 先别急着给自己下结论／也不用逼自己马上振作／也很正常／先缓一缓／我陪你 | 像朋友那样接一句实在话，然后问具体的事 |
| H4 | 如果你想，我可以生成一张……你想让我做吗 | 删 |

- 原：听起来你对自己很失望，心里也挺难受的。先别急着给自己下「干不好」的结论，也不用逼自己马上振作起来。
- 改：怎么了？是今天哪件事没弄好，还是最近一直不顺？（molang163 原例）

证据：
- 【社区】1768077 41 楼整段仿写；1924570 主楼「谄媚/讨好类」。
- 【报道】爱范儿等报道「稳稳接住你」成为网络梗；TechCrunch 报道 OpenAI 称 GPT-5.3 Instant 减少了让人反感的语气。<https://www.ifanr.com/1665148>、<https://techcrunch.com/2026/03/03/chatgpts-new-gpt-5-3-instant-model-will-stop-telling-you-to-calm-down/>
- 【仓库】molang163 列出 GPT-6.1-Sol 的安慰套话：「先别急着给自己下结论」「也很正常」。

## I. 标点与排版

### GPT-I1 全角分号「；」串长句

GPT-6.x 用分号把三四个分句串成一句，读起来像条款。

- 原：结构检查通过；模块入口仍可导入；输出路径使用绝对路径；不受目录变化影响。
- 改：结构检查通过了。换了目录也能正常导入和输出。

证据：【本机】「；」GPT-6-Luna 1285、6.1-Terra 1077、Astra 648、6.1-Sol 503 次/10 万字，Claude 300。

### GPT-I2 给自造概念加引号

GPT-6.1-Sol 爱用引号给一个词套上特殊含义：把「新」落实为、所谓「集中」不等于……

- 原：「集中」不等于把所有参数塞进一个巨大的 YAML。
- 改：配置集中放，但不用全塞进一个文件。

证据：【本机】左引号 GPT-6.1-Sol 433 次/10 万字，Claude 153；【社区】1768077 82 楼「喜欢用特定称谓的引号」。

### GPT-I3 加粗整句结论

GPT-6.1-Sol 爱把一整句结论加粗，常常是一句防御性的话：**尚未提交，也未运行测试。**

- 改：要加粗只加粗一个关键词，或者不加。防御句按 A 类处理。

证据：【本机】「**」GPT-6.1-Sol 1726 次/10 万字，Luna 281。Claude 更多（3059），所以「加粗多」本身不是 GPT 的判据，「加粗的是防御句」才是。

### GPT-I4 几乎不用破折号

GPT-6.x 很少用「——」（0–9.5 次/10 万字，Claude 14.4）。GPT-5.1 起 OpenAI 有意压低破折号。所以文本里破折号很多，反而不太像 GPT-6.x。

证据：【本机】；Wikipedia「Signs of AI writing」13.5 节提到 OpenAI 的 GPT-5.1 有意减少破折号。<https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing>

## J. 篇幅失控

随口问一句，回七段加一张表。

- 改：第一句回答问题。问「能不能」「要不要」，第一句就是「能」「不用」。说完就停，读者想多听会接着问。

证据：【仓库】molang163「问一句能不能拿某个游戏角色做皮肤卖，回了七段加一张表」；原版 GPT-6.1-Sol 回答字数中位数 408，加了 skill 后 244。【社区】linux.do「受不了 gpt 了」1 楼：GPT-6 开始喜欢说一堆废话，又臭又长。<https://linux.do/t/topic/2990749>

## 写给 Codex 的 AGENTS.md 片段（可选）

molang163 的测试显示，只装 skill 时长对话后几轮还会回到防御腔，把核心规则写进 `~/.codex/AGENTS.md` 后没再出现（GPT-6.1-Sol，30 轮里 3 轮 → 0 轮）。下面是按本清单写的五条：

```markdown
## 中文回复
- 第一句回答问题。说完就停。
- 不写防御性的话：不说「不代表」「不能证明」「尚未」「未修改」「没有证据表明」，除非读者接下来要据此行动。
- 错了说「刚才说错了」，然后给对的，不解释自己为什么说得太绝对。
- 不用自造名词：收据、验收、本轮、口径、链路、显式、兜底、闭环、收口。换成当面能说出口的话。
- 少用分号串句，不给普通词加引号，不加粗整句。
```
