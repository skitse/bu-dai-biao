## 自动发现

用 2–4 字 n-gram 的对数优势比（Codex 对 Claude，文档数 ≥ 25）找两边差异最大的词。Codex 一侧排在前面的非领域词：我会、验证、实际、保留、当前、独立、候选、明确、核对、现有、验收、修复、执行、继续、不能、审查、复核、尚未、边界、因此、避免、已完成、未运行、本轮、显式、补齐、收据、交付。Claude 一侧：所以、一个、现在、改成、还没、只有、不是、就是、出来、一下、比如、你说、这是、一遍、写进、我没、需要你、不用、另外、而且、好了。

可以看出：GPT-6.x 偏书面、偏流程词（核对、验收、执行），Claude 偏口语（所以、就是、一下、好了）。

## 局限

- **只有一个用户。** 任务以生物信息学流程、iOS App、课程材料为主。「验证」「环境」「数据库」这类词的差距有一部分来自任务不同，所以 references 只收了非领域词。
- **系统提示不同。** Codex 和 Claude Code 各有自己的系统提示，用户也写了 AGENTS.md / CLAUDE.md。比如 Codex 系统提示要求少打断用户，所以 GPT 的「要不要我」在这里是 0，但 ChatGPT 网页端社区报告很多。
- **Claude 的加粗、冒号多**，很大程度上来自 Claude Code 和桌面端的输出格式，纯 API 写作不一定（Sun et al. 2025 的 Claude 3.5 Sonnet 很少加粗）。
- **扫描脚本是在同一批语料上调出来的**（在这批语料上，`scan.py` 的 GPT 分：Codex 26.1、Claude 6.7 每千字单位），没有独立测试集，别把它当检测器。
- 小于 5 次/10 万字的差异不可靠。
